# ADR-0005: 权限系统插件化（core 提供钩子，策略外置）

- 状态：已接受（首版落地 + 审批链路均 2026-08-09）
- 日期：2026-08-09

## 决策

权限/安全模型**插件化**：core 只在工具执行的关键路径提供**检查点钩子**（如 bash 执行前、文件写入前），审批策略由**插件实现**。默认提供一个审批插件（允许/拒绝/总是允许），策略可替换为白名单、全放行、外部策略服务等。

## 调研对标

| 项目 | 权限模型 | 对比 |
|---|---|---|
| **Pi** | **不内置权限系统**——"Pi does not include a built-in permission system for restricting filesystem, process, network, or credential access"，安全边界委托给外部容器化（Gondolin / Docker / OpenShell） | 核心最简但无容器时裸奔 |
| **Codex** | 内置审批：三种模式（on-request / on-failure / never）+ sandbox 策略（workspace-write / read-only），OS 级沙箱（Seatbelt/Landlock/bwrap） | 策略写死进 core |
| **OpenCode** | 内置权限：`permission.Check(action, resource)`，auto-approve / prompt / deny | 策略写死进 core |

本项目：**权限做成插件**——core 只提供检查点钩子，策略由插件承载，可替换、可演进。与本项目"策略外置为插件"的总架构哲学一致（同 ADR-0004：core 只做编排，行为由插件注入）。

## 候选方案与权衡

1. **内置审批**（Codex/OpenCode）——逐次询问用户，第一版即可用，但策略写死进 core。
2. **不内置，委托容器**（Pi）——core 极简，依赖容器化隔离，但无容器时裸奔。
3. **权限做成插件（选定）**——core 只提供检查点钩子，策略由插件承载，可替换、可演进。

选定方案 3。

## 首版落地（2026-08-09）

首版权限插件实现**最小策略：永远允许（放行所有）**。目标不是安全，而是打通「core 检查点 → 权限插件裁决 → 工具执行」的链路验证。真实的审批策略（允许/拒绝/询问）在插件机制稳定后替换。

## 审批链路（2026-08-09）

**core 永远是审批的发起方**。检查点触发后，core 发出审批请求——首版插件直接通过；未来插件返回 ask 时，core 向**用户交互界面（TUI/gui 等 QUIC 客户端）**发审批请求，界面渲染询问并回传裁决。权限插件不感知任何交互界面，core 是中枢。

用户原始表述："core永远发出信息要求审批, 首版插件的逻辑是直接通过, 后续再向tui/gui等用户交互界面发"。

候选对比：
- **core 中枢代理询问（选定）**——插件只返回 allow/deny/ask，core 代表插件走跨进程询问链路。插件不感知 TUI，隔离干净。
- **插件直连 TUI 询问**——插件拿 TUI 端点自己调。插件要知道 TUI 存在和地址，耦合紧，违背插件不感知客户端的隔离。
- **TUI 轮询审批队列**——多一套轮询机制，审批延迟，且竞态（审批结果 vs 工具已超时）。

## 后果

- core 需要定义权限检查点接口（危险工具执行前回调，可返回放行/拒绝/询问）。
- 第一版交付 perm-allow-all（永远允许）插件。
- 安全检查点独立于工具实现——同一检查点适用于所有危险工具。
- 权限策略演进不触碰 core 和工具实现。
- 审批请求在协议层走推送流（全可靠，PROTOCOL.md），裁决经 `POST /approval-response` 回传。

## 审批等待实现（2026-08-10 补充，ADR-0002 线程模型的依赖）

权限插件返回 `ASK` 时，agent **真等用户裁决，绝不按 allow 放行**：

- 询问**只发往用户交互界面（TUI/gui）**，core 不自行裁决。
- agent 线程：executor 检查点遇 ASK → 发 `permission_request`（事件队列 → 推送流）→ **阻塞在条件变量**等裁决。
- 事件循环线程：持续收 `POST /approval-response`（body `{id, allow}`）→ 匹配挂起请求 → 唤醒 agent 线程。
- 超时（30s）按 deny（危险工具默认拒绝，宁可不执行）。
- 依赖 ADR-0002 线程模型：agent 独立线程 + 事件队列，否则事件循环线程被 agent 占住无法收裁决。
