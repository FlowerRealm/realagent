# ADR-0009: 模型元数据归插件，计价不进 core

- 状态：已接受
- 日期：2026-08-13

## 决策

core 定义 `Model` 类型并持有模型注册表，但**不内置任何模型数据、不参与计价**：

1. **数据归插件**：模型数据表（含单价）是 Provider 壳自己的文件，壳自己读、自己解析。core 不读它，也不经配置注入机制搬运它。
2. **清单经 ABI 上报**：壳经新增的 `list_models`（ABI 1 → 2）把 core 用得着的字段报上来——`name` / `owned_by` / `context` 三项，**单价不报**。
3. **计价在壳里**：壳拦下协议层解析出的 token 用量事件，按本次调用的模型查自己的表算出钱数，只向上 sink `status_update {"cost": x}`。token 不跨 core 边界，core 侧 `Usage` 结构体连同全部 token 字段删除。
4. **core 只累加**：按 agent 实例跨 turn 累加 cost，经 `status_update` 帧下发（本次 run 累计的绝对值，客户端覆盖写）。
5. **打包产物与运行时配置分离**：包内 `models.json` 是出厂数据（只读，随插件升级更新）；`~/.realagent/models/<插件名>.json` 是用户接管版，**存在即整体接管**，两者不合并。

## 候选方案与权衡

### 模型清单怎么进 core

1. **plugin.json 加 `models` 键**——零 ABI 改动。但清单一旦成为用户可改的运行时数据，plugin.json（打包产物）就装不下它了；且 manifest 的可选键拼错会静默失踪，正是 loader 严格解构要防的失败模式。
2. **core 读模型数据表**——core 要理解一份它不该理解的数据（单价形状随供应商而异），且违反"数据归谁谁解析"。
3. **`list_models` C ABI（选定）**——插件读文件、解析、算钱全在自己家，只把 core 用得着的子集报出来。函数签名写错编译不过，拼不出静默失踪。代价是 ABI 1 → 2、6 个 plugin.json 改版本号、插件全量重编。

### 计价放哪

1. **core 做点积**（pricing 与 usage 同名键相乘）——core 代码最少，但要求单价数据流经 core，与"数据归插件"冲突；且单价随模型变，core 得替插件维护"这次用哪个模型"的对应关系。
2. **壳里算（选定）**——单价随模型走，本来就是供应商知识；壳在 `parse_feed` 里已经能看到内层解析出的 token 用量，就地乘完即可。代价是 `parse_feed` 不再纯透传。

### cost 累计放哪

1. **TUI 累加**——core 零状态，但那是增量语义，与 PROTOCOL.md「绝对值，非增量，丢帧不产生永久偏差」冲突；且 TUI 不知道 run 边界，只能从 `agent_start` 推断。
2. **壳自己累加**（订阅 `agent_start` 清零）——core 连 `cost` 这个键都不用认识。但壳是单例，多 agent 并发（第二版里程碑）时多个 agent 共用一个壳实例，累计状态直接串账。
3. **core 累加（选定）**——core 累加一个 `double` 不需要知道任何单价、任何 token 维度、任何供应商身份，它做的是本来就在做的事：管 run 的生命周期。天然按 agent 实例隔离。

## 后果

- `plugin_api.h` ABI 升 2，`plugin_api_t` 增 `list_models`；协议层（v1-messages）返回 `NULL`——模型属于供应商身份，清单不沿嵌套链透传。
- `parse_feed` 从「纯透传」放宽为「默认透传、按需拦截改写」，与 CONTEXT.md `Plugin Nesting` 的「外层可对内层输出做任意修改」对齐。首版 deepseek 壳拦 usage 换 cost 是第一个用例。
- 推送流新增 `status_update` 帧（开放键集，core 除 `cost` 外不认识任何键），替代原 `usage` 帧；`GET /status` 改名 `GET /statusline`（它喂的是状态栏，不是状态行）。
- TUI 状态行的 token 段改为花费段。
- **不兜底**：模型表解析失败即插件加载失败并报错原文（不跳过坏条目）；模型重名后写覆盖（不检测）；配置的模型名不在表里不检查、不警告——表是参考资料，不是白名单，供应商发新模型时用户不该被自己的 agent 锁在门外。

  > ⚠️ **"模型重名后写覆盖（不检测）"已被 ADR-0011 取代（2026-08-15）。** 注册表改按 **(插件, 模型名)** 建键：多个 Provider 壳报同一模型是**预期行为**（同一模型的多条到达路径——DeepSeek 直连 / OpenRouter，上下文窗口相同但端点、凭证、单价各异），压成一个键就是丢信息。用哪条路径看当前 provider。重名因此不再发生，无需检测。本条其余两句（解析失败硬错、表不是白名单）不变。
  >
  > 同时：`list_models` 原定"内存归插件所有，core 只读不释放"的特例取消——跨边界内存统一由 `core->api->alloc` 分配、core 释放。
- 用户一旦创建运行时模型表，就吃不到插件升级带来的新模型。这是显式接管的代价，core 不在背后往用户的表里塞东西。
