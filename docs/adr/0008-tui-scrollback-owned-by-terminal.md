# ADR-0008: TUI 历史归终端管（不用 altscreen）

- 状态：**已被取代**（ADR-0020，2026-08-28）
- 日期：2026-08-11

> 本 ADR 的核心决策已被 [[ADR-0020]] 推翻：TUI 进 alternate screen，历史从会话记录
> 动态渲染。理由是 ADR-0019 带来了一件这里没有位置的事——**切 agent**：scrollback 是
> 一条只能追加的时间线，表达不了「换一个源」，而一个在后台跑过的 agent，它的行从来
> 没被打进这个终端过。**「定型」与提交保序（`outbox`）随之一起删除**，它们存在的唯一
> 理由是判断哪些行可以立刻 `tea.Println`。
>
> 本文档保留：这里记的代价（退出即消失、不能管道、滚出屏幕才能选）是 ADR-0020 买单
> 买回来的那一份，逐条对得上。

## 决策

TUI **不进 alternate screen**。已定型的输出行用 `tea.Println` 打进**终端原生 scrollback**，Bubble Tea 只重绘底部**活动区**（未定型行 + 审批框 + 斜杠菜单 + 读秒状态行 + 输入框）。

滚动、选中、复制、搜索全部复用终端自带能力；TUI 不实现 viewport，也不开鼠标模式（那会抢走滚轮）。

## 背景

M6 首版把消息存为 `[]message`，`View()` 里按 `\n` 切行后硬切尾巴：

```go
if len(lines) > avail { lines = lines[len(lines)-avail:] }
```

三个问题一个根因——**渲染层没有「行」这个概念**：

1. **翻不了历史**：切掉的行永远看不到，altscreen 又屏蔽了终端自身的 scrollback。
2. **行数统计是假的**：不折行，一段 300 字的中文回复被算作 1 行，实占 4 行。`avail` 这套账全错，内容溢出、输入框被顶出屏幕。
3. **ANSI 烤进了数据**：工具状态行带着转义序列拼进模型正文（`streaming.text += toolStyle.Render(...)`），宽度变了无法重排，`len(line)` 数的是字节。

## 候选方案与权衡

1. **交还终端（选定）** —— 终端已经有 scrollback、滚轮、选区、`Cmd+F`，重写一遍纯属浪费；输出退出后仍在，可管道、可 `tee`。claude code / codex 均如此。代价：终端改宽后**旧内容不重排**（所有 inline CLI 通病）。
2. **自建 viewport（altscreen）** —— 改宽能重排历史，但滚动/选中/复制全要自己实现，退出即消失，鼠标模式抢走滚轮。

选定 1。

## 核心不变量

> **追加式文本的贪心折行是前缀稳定的**——往末尾加字不会改变前面的断点。

于是定型判据只有一条、没有特殊情况：**除最后一个折行外，所有折行都已定型，可以立刻打进 scrollback**。长段落流式输出时活动区恒定只剩一个折行，不会越长越高把屏幕撑爆。

单元测试 `TestFreezeIncrementalEqualsWhole` 直接压这条不变量：逐字流式喂入的提交结果，必须与整段一次性渲染逐行相同。

## 配套改动

- **行模型**：`line{role, text}` 取代 `message{role, text, thinking}`。数据里不含 ANSI，样式在渲染最后一刻套上。thinking / 工具行按到达顺序进同一条行流，`streaming` 这个特殊状态被消掉，只剩「末行是否还开着」一个 bool。
- **折行**：`ansi.Wrap` 按显示宽折行（中文 2 列、ANSI 不计宽），首行带角色前缀、续行挂起缩进。
- **提交保序**：`tea.Cmd` 各跑各的 goroutine，多条 `Println` 同飞会乱序且不可挽回。立铁律——**同一时刻只许一条 Println 在飞**，其余排队（`outbox`）。
- **输入行编辑器**：`[]rune` + 光标下标。原实现 `input[:len(input)-1]` 按字节退格，会把中文劈成半个字符。

## 后果

- 终端改宽后已提交的历史不重排（新内容按新宽度折）。
- 会话记录留在终端 scrollback 里，退出后仍可翻阅、可复制。
- 活动区**绝不能高过终端**——否则 Bubble Tea 自行截断、光标算错就花屏。`View()` 末尾有兜底截断，正常情况下不会触发。
